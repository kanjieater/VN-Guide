# VN Guide

A mobile-optimized, step-by-step walkthrough app for visual novels, automatically generated by Claude using Japanese and English source walkthroughs.

**Live site:** [kanjieater.github.io/VN-Guide](https://kanjieater.github.io/VN-Guide/)

---

## How it works

A Docker container watches a VNDB "playing" list. When a new game appears on the list, Claude Code fetches at least two Japanese walkthroughs, cross-validates them, and generates a structured route guide as JSON. The JSON is pushed to GitHub Pages immediately — routes appear live but tagged "unverified" until they pass an automated accuracy review.

```
VNDB playing list
      ↓
  generate.py        — scaffolds game directories, updates index.html
  guide_gen.py       — invokes Claude Code (author agent) to generate route JSON
                        routes go live immediately with reviewed: false
  review.py          — alternates reviewer and author agents in separate sessions
                        reviewer creates GitHub issues → author fixes → repeat
                        marks routes reviewed: true when reviewer finds no issues
  deploy.py          — git commit + push to GitHub Pages
      ↓
games.json + guide.json + route_*.json
      ↓
  guide-app.js       — browser SPA, fetches JSON, tracks progress locally
                        unreviewed routes show an "unverified" badge
```

### Review workflow

Accuracy review is adversarial by design: the reviewer and author agents always run as separate Claude invocations with no shared context, so the reviewer cannot be biased by the author's framing. Review issues are tracked as GitHub issues labeled `route-accuracy` and the game slug. A route's "unverified" badge is removed only after the reviewer runs a clean pass (no open issues).

## Repository structure

```
/
├── guide-app.js              # Shared browser app (all games load this)
├── style.css                 # Shared styles
├── index.html                # Landing page (auto-generated from games.json)
├── games.json                # Registry of all games (VNDB ID → slug, metadata)
├── <game-slug>/
│   ├── index.html            # Minimal shell (auto-generated — do not edit directly)
│   ├── guide.json            # Route list + metadata (reviewed: bool per route)
│   └── route_<id>.json       # Steps for one route
├── scripts/
│   ├── generate.py           # Scaffold + landing page regeneration
│   ├── guide_gen.py          # Claude Code invocation loop (author agent)
│   ├── review.py             # Automated review loop (reviewer ↔ author, separate sessions)
│   ├── deploy.py             # Git commit + push
│   ├── pull_vndb.py          # VNDB API sync
│   ├── refresh_oauth.py      # Claude OAuth token refresh
│   ├── prompts/              # Per-game prompt overrides
│   └── templates/
│       ├── guide_stub.html   # Template for each game's index.html
│       └── landing.html      # Template for root index.html
├── .claude/
│   ├── agents/
│   │   ├── guide-author.md   # Author agent instructions
│   │   └── guide-reviewer.md # Reviewer agent instructions
│   └── workflows/
│       └── guide-review.md   # Review lifecycle documentation
├── Dockerfile
└── entrypoint.sh             # Container main loop
```

## Contributing a guide

Guides are generated by Claude Code, not hand-authored. The recommended contribution path is to run the container locally against your fork, let Claude generate the guide, then open a PR.

### 1. Fork and set up

```bash
git clone https://github.com/<your-username>/VN-Guide.git
cd VN-Guide
```

Enable GitHub Pages on the `main` branch of your fork (Settings → Pages → Deploy from branch → main).

### 2. Create a `.env` file

```env
VNDB_USER=your_vndb_username
GITHUB_TOKEN=ghp_...                   # Personal access token with repo scope
GIT_EMAIL=your-bot@example.com
GIT_NAME=VN Guide Bot
REPO_PATH=/app/repo
GUIDE_WINDOW_DISABLE=1                 # Generate at any time (not just 22:00–00:30)
GUIDE_PRIORITY_VID=v1234              # VNDB ID of the game you want to add
```

Use either an API key or shared Claude OAuth credentials (see below).

### 3. Run the container

```bash
docker compose up
```

Claude Code will research at least two Japanese walkthroughs for the target game, cross-validate them, and write the route JSON files. When `GUIDE_PRIORITY_VID` is complete, the container exits automatically.

### 4. Open a PR

Push your fork's output branch and open a PR to `kanjieater/VN-Guide`. Include only the generated JSON files (`games.json`, `<slug>/guide.json`, `<slug>/route_*.json`) — the `index.html` files are regenerated automatically and should not be included.

## Self-hosting the full pipeline

If you want the container to run continuously and auto-generate guides for every game on your VNDB playing list:

### Requirements

- Docker
- A VNDB account with a "playing" list
- An Anthropic API key (or Claude OAuth session — see below)
- A GitHub repo with GitHub Pages enabled

### Environment variables

| Variable | Default | Description |
|----------|---------|-------------|
| `VNDB_USER` | | VNDB username (also used for GitHub auth) |
| `GITHUB_TOKEN` | | GitHub PAT with repo scope |
| `GIT_EMAIL` | `vn-guide-bot@shke.xyz` | Git commit author email |
| `GIT_NAME` | `VN Guide Bot` | Git commit author name |
| `REPO_PATH` | `/app/repo` | Path to the cloned repo inside the container |
| `ANTHROPIC_API_KEY` | | Anthropic API key (optional if using OAuth) |
| `RUN_INTERVAL_HOURS` | `6` | Hours between sync cycles |
| `GUIDE_START_HOUR` | `22` | Start of generation window (24h local time) |
| `GUIDE_END_HOUR` | `0` | End hour of generation window |
| `GUIDE_END_MIN` | `30` | End minute of generation window |
| `GUIDE_WINDOW_DISABLE` | | Set to `1` to generate at any time |
| `GUIDE_PRIORITY_VID` | | VNDB ID to generate first; container exits when done |
| `GUIDE_REVIEW_MAX_ROUNDS` | `5` | Max reviewer/author cycles before giving up on a game |
| `GUIDE_REVIEW_MODEL` | `claude-sonnet-5` | Model used for reviewer and author agents |
| `GUIDE_REVIEW_TIMEOUT` | `3600` | Seconds before a single reviewer or author call times out |

### Using Claude OAuth instead of an API key

If you have a Claude subscription, mount your host Claude Code credentials into the container:

```yaml
# compose.yml
volumes:
  - ~/.claude:/home/guide/.claude
```

The container refreshes the OAuth session automatically.

### Pointing the container at your fork

Update the remote URL in `entrypoint.sh`:
```bash
"https://github.com/<your-username>/VN-Guide.git"
```

Then build and run:
```bash
docker compose up -d
```

## Local development

```bash
cd /path/to/vn-guide
python3 -m http.server 8765
```

Open [http://localhost:8765](http://localhost:8765) for the landing page, or `http://localhost:8765/<game-slug>/` for a specific guide.

## UI changes

All guide logic lives in `guide-app.js`. The per-game `index.html` files are minimal shells generated from `scripts/templates/guide_stub.html` — edit the template, not individual game files. The container re-copies the template on every cycle and injects a content hash of `guide-app.js` for cache busting.
